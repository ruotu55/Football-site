# Video — Play, Record, Render

Three ways a quiz becomes a video. All share the same in-browser flow; they differ in how frames are captured.

## 1. Play (in browser)
`video.js` `startVideoFlow()` → enables video mode on all levels → ball preloader intro (`.Storage/shared/ball-preloader-animation.js` `playBallPreloader`, GSAP merge→bounce→reveal) → `runVideoStep()` walks levels via `switchLevel()` (`levels.js`) with GSAP grid-overlay transitions (`transitions.js`). Each question: countdown → reveal (pitch/header flip in `pitch-render.js`) → reveal voice (`audio.js`). Pages are `html/{logo,landing,outro}.html`. Natural end fires `recording-naturally-finished` → `stopVideoFlow()`.

**Per-question countdown length** (runner 1 Regular): `QUESTION_COUNTDOWN_SECONDS` const at the top of `video.js` (currently **3s**, was 10s) drives `runVideoStep()`'s question branch — the timer circle drain, ticking, and colours (3=green/2=yellow/1=red+pulse) all derive from it. Applies to Play/Record/Render (one shared flow); the answer-reveal (voice + flip) is unchanged and runs after. Retune in one place. (`video.js` is imported with a `?v=` token in app.js / render-mode.js / render-segments.js — bump all three together on edit.)

## 2. Record (OBS)
`recording-flow.js` `startRecordingAndFullscreen(savedName, language)`:
1. **Preflight** (`recording-preflight.js` + shared `recording-preflight-core.js`): freeze each level's reveal phrase, collect logo/photo/voice/emoji URLs, **warm** them (preload). Team logo is a **hard gate** (`{critical:true}`) — if the crest can't load, recording is blocked (no "record anyway"). Non-critical misses warn only.
2. **OBS** (`obs-recorder.js`, obs-websocket-js v5 → `ws://localhost:4455`, no auth): `loadObsConfig(language)` from `/__obs-config`, create/refresh a Window/Screen Capture source, strip global audio inputs, `SetRecordDirectory` to `Ready videos/<Lang>/`, start. ~2.8s audio warmup before start if the capture source changed.
3. Run the play flow; on finish `stamp` the recording timestamp into the block.
- **Record-language chooser** (shared `record-language-chooser.js`): English / Spanish / Both. "Both" records EN then ES (`appState.doubleRecording`).
- **Mac split**: when `999_Mac_Uploader` runs, OBS record-dir + upload route to the Mac (localhost:9876).

## 3. Render (headless, frame-by-frame) — `render/`
Deterministic puppeteer + CDP virtual-clock render. Orchestrator `render/index.mjs`:
1. **PROBE** — `launchRenderPage()` (no capture), run the flow advancing virtual time frame by frame to count `totalFrames`, capture voice `durations` + audio `manifest`.
2. **CAPTURE** — spawn worker(s) (`worker.mjs`, default 1). Each re-runs the identical flow with the duration map injected, screenshots its frame window, pipes JPEGs into ffmpeg → segment MP4.
3. **CONCAT** — ffmpeg concat the segments → silent.mp4.
4. **AUDIO + MUX** — `audio-mux.mjs` + `audio-filtergraph.mjs` rebuild the soundtrack from the manifest (BGM crossfade + voice ducking) and mux onto the video.

**Render mode page side** (`render-mode.js`): URL `?render=1&lang=&script=&fps=60[&segment=]`. Seeds `Math.random` (mulberry32), exposes `window.__render` (`ready/done/start()/getDurations()`), `window.__renderDurations` (injected), `window.__renderScript` (live on-screen state, preferred over saved-by-name), `window.__audioManifest`. `start()` fires `_startFn` without awaiting; the driver advances the clock.

**Test clips** (`render-segments.js`): render just one segment. Catalog is **exactly 3 clips** (`RENDER_TEST_SECTIONS`):
- `intro` — **0.5s background-only hold** → 4-ball merge → bounce → circular reveal of Level 1 (landing). Cap-bound (~300f); the GSAP preloader promise does **not** resolve under virtual time, so it relies on the frame budget, not a natural finish. The 0.5s hold is render-only (gated on `window.__render?.active` in shared `ball-preloader-animation.js` `playBallMerge` — liquids start `opacity:0`, the merge timeline is offset by `HOLD`); Play/Record intros are unchanged. If you change the hold, keep the intro budget in `render/segment-budgets.mjs` **and** `js/render-segments.js` in sync (60fps frames; 0.5s = 30f).
- `level-playing` — first question plays out (10s countdown + reveal) **then transitions into the next level**; `video.js` ends the clip once the next level is on screen (gate `window.__renderSegment === "level-playing"` in `revealCurrentLevel`'s post-transition callback). ~834f.
- `ending` — jumps to the last question, holds ~3s, then `revealCurrentLevelForRenderTest()` runs the **real** reveal→outro flow; `levels.js` plays the full ending voice+animation and fires `recording-naturally-finished` (render-mode sets `done`). ~740–870f.

Frame caps in `SEGMENT_FRAME_BUDGETS` (mirror in `render/segment-budgets.mjs` — keep both in sync). UI: `render-test-clips-ui.js` (renders `RENDER_TEST_SECTIONS` generically); progress UI: `render-progress-ui.js`. To add/rename a clip: edit the catalog + both budget maps, add a runner in `RUNNERS`, and (if it should stop mid-flow) add a `window.__renderSegment` gate in `video.js`.

**Quality / fps:** the render driver is fps- and resolution-aware. The main **Render Video** button opens a **Render options dialog** (`js/render-options-dialog.js` `askRenderOptions()` → `{fps, height}`) — **FPS** 30/60 (default 60) and **Resolution** 1080p (1920×1080) / Current 2560×1440 (default, `height 1440`) / 4K (3840×2160). The picks ride the `/__render-video` POST body (`fps`, `height`) and `run_site.py` forwards them as `--fps`/`--height` for the full render. **Test clips** ignore the dialog and stay **1080p @ 30fps** (`run_site.py` forces `--fps 30 --height 1080` whenever `segment` is set; the worker also uses `-preset ultrafast -crf 23` for previews). Threaded through `--fps`/`--height` → `index.mjs` (scales the budget by `fps/60`, computes `videoMs = totalFrames/fps`) → `worker.mjs` (ffmpeg `-framerate/-r/-s` from `frameSizeForHeight(height)`) → `lib.mjs launchRenderPage({fps,height})` (virtual-clock step `1000/fps`, viewport `deviceScaleFactor = height/972`). `SEGMENT_FRAME_BUDGETS` are authored as **60fps** frame counts and scaled to the actual fps. **Server restart needed** to apply the `run_site.py` change.

**Headless launch** (`lib.mjs` `launchRenderPage`): puppeteer `headless:"new"`, viewport 1728×972 @ deviceScaleFactor 2560/1728 → **2560×1440** frames. CDP `Emulation.setVirtualTimePolicy` pause→advance in 16.667ms (60fps) budgets; capture via `Page.captureScreenshot` jpeg.

### ⚠️ CRITICAL render gotcha — "stuck at frame 1"
Under **paused virtual time**, `Page.captureScreenshot` **deadlocks** waiting for a compositor commit that never comes, as soon as a compositor-promoted animation (GSAP `force3D`/`willChange`, e.g. the ball-preloader `opening` clip) is running. The probe (no capture) is unaffected, so the symptom is: probe reports totalFrames, worker stalls at `captured=1`.
**Fix (applied):** launch with `--run-all-compositor-stages-before-draw --disable-new-content-rendering-timeout` (in `lib.mjs` args). Forces a frame commit per advance. `beginFrame` is NOT available in `headless:"new"`; `fromSurface:false` does not help. When mirroring render to sibling runners, copy these flags. (An x264 `malloc failed` seen mid-debug was just transient OOM from overlapping test Chromes, not a real bug.)

### Gotcha — render intro revealed a blank bg, the landing text popped in late
Two separate causes, both render-only:
1. **(Primary) `render-mode.css` hid the whole landing for the entire preloader.** The rule `body.render-mode-active.ball-preloader-active .landing-page { visibility:hidden }` kept the landing invisible the *whole* time the preloader was up — **including during the ball reveal**. So the radial mask opened onto a hidden landing (blank stage colour) and the text only "appeared" when the preloader hid and that class dropped. **Fix:** gate it on `:not(.revealing)` via `:has()` — `body.render-mode-active.ball-preloader-active:has(.ball-preloader:not(.revealing)) .landing-page`. Now the landing is hidden only during merge/bounce; once `.revealing` is added the mask exposes the real landing + text progressively, exactly like Play.
2. **(Secondary) composited CSS animations run at the WRONG speed under virtual time.** A CSS `@keyframes` on a composited property (`transform: translate3d`) is **not** synced to the CDP virtual clock — the compositor advances it on **real wall-clock time**, so it ran far **too fast** in the output (each captured frame takes >1/fps real time, so the bob over-advances per captured frame). Cases: the landing title `.landing-motion-group` `float-up-down 3.2s` **and the pitch player circles** `.player-slot.has-player > .slot-mount` `float-up-down 4s`. RAF-driven GSAP tweens animate correctly (virtual-synced). **Fix:** landing → `startRenderLandingFloat()` in `coverLandingForRenderIntro()` (render-segments.js) — `animation:none` + GSAP yoyo `y:-12, duration:1.6, sine.inOut, repeat:-1` (matches 3.2s). Pitch circles → `applyRenderSlotFloats()` at the end of `renderPitch()` (pitch-render.js) — per-mount `animation:none` + GSAP yoyo `y:-12, duration:2, sine.inOut, repeat:-1` (matches 4s); flagged `dataset.renderFloat` so re-renders don't reset the bob. Render-only (`window.__render?.active`); Play/Record keep the CSS animation. **Rule of thumb: anything that must animate during a render must be GSAP-driven, not a composited CSS keyframe — and the same applies to CSS *transitions*.** The countdown ring (`.timer-progress` `stroke-dashoffset`) used a `transition: stroke-dashoffset 1s linear` stepped once per second; under the virtual clock the transition didn't interpolate (it snapped each tick), so the ring jumped in 1s chunks. Fix (video.js, render-gated): one smooth `gsap.fromTo(circleEl, {strokeDashoffset:0}, {strokeDashoffset:dashLength, duration:drainTotalTime, ease:"none"})` and skip the per-second `strokeDashoffset` step updates while `window.__render?.active`. Play/Record keep the CSS transition. **Same fix for the team-header sidebar slide-in** (`.team-header` `transition: transform 0.5s ease-out`, toggled by `.team-header--show` in `pitch-render.js syncTeamSidebarPanel`) — it snapped in instantly in render; render-gated `gsap.fromTo(th,{xPercent:-100},{xPercent:0,duration:0.5,ease:"power1.out", onComplete:add .team-header--show + clearProps})`.

### Gotcha — async server fetch during the flow → long dead tail on the ending screen
**Symptom:** a full render ended with ~30–40s of static ending (like/subscribe) screen. **Cause:** the PROBE pass measures voice timing *live*; the **ending voice** is resolved through an async server round-trip (`window.__resolveEndingVoiceSrc` → `/__ending-voice/status`, maybe `/__ending-voice/generate`). That fetch runs in **real time while the probe's virtual clock keeps racing ahead** (the driver advances time without waiting on network), so by the time it resolves ~tens of virtual-seconds have elapsed → `recording-naturally-finished` fires late → inflated `totalFrames`. The CAPTURE pass uses *injected* durations so it times the outro correctly (~real position) but still captures up to the probe's inflated count = static tail. **Fix:** `render-mode.js` setup (runs in real time, before the clock starts) pre-resolves the selected ending type's voice src, caches it, prewarms its duration (`renderPrewarmVoiceDurations`), and wraps `window.__resolveEndingVoiceSrc` to return the cached src synchronously — so `playCommentBelow()` resolves at the correct virtual time and the render ends ~1s after the ending voice. **General rule: any async server fetch on the live render path will diverge the probe's clock — resolve/prewarm it during setup, before the virtual clock runs.**

### Gotcha — Cloud Drift bleeding into the intro
The forced **Cloud Drift** transition (`new-1`, `levels.js` `isLandingToFirstQuiz`) that runs landing→Level-1 was appearing **over the ball-preloader intro** in render only. Cause: a Cloud Drift fired during boot/script-apply (an early level switch) and was still fading out on the virtual clock when capture began — `.new1-overlay` sat at `opacity:1` from frame 0 (seen even in the `intro` test clip, which never triggers a transition itself). Fix: `transitions.js` exports `resetTransitionOverlays()` (kills GSAP tweens + zeroes opacity on every overlay container), called from `coverLandingForRenderIntro()` (runs synchronously at the start of both the full-render `_startFn` and `runIntro`, before frame 0). The real landing→Level-1 Cloud Drift still runs normally afterward. Import `transitions.js` with the **same specifier** (`"./transitions.js"`, no `?v=`) or the reset hits a different module instance and the live overlays aren't found.

**Server endpoints** (`run_site.py`): `POST /__render-video` (body `{script, language, scriptObject?, segment?, fps?, height?}` — `fps`/`height` honoured only for full renders, validated to {30,60} / {1080,1440,2160}) spawns `node render/index.mjs …`; `GET /__render-video/progress?job=<id>` streams stage JSON (`probe/probed/capture/progress/concat/audio/done`); `POST /__render-video/delete` (body `{path}`) deletes a rendered file — validated to be under `Ready videos/` (403 otherwise). Gated by `RENDER_FEATURE_ENABLED`. Output: `Ready videos/<Lang>/<script>.mp4` (or `…/render-tests/<script> - <segment>.mp4`).

**Done-state preview** (`render-progress-ui.js` `setRenderProgressDone(path)`): when a render finishes, the progress modal shows **▶ Play** (inline `<video>` — builds a servable URL by slicing the absolute path at `/Ready videos/` and `encodeURIComponent`-ing each segment; the dev server serves the repo root) and **🗑 Delete** (POST `/__render-video/delete`). Self-contained in the progress UI; `app.js` only passes `m.path`.

## PROD validation
`prod-validation.js` + shared `prod-asset-validation.js`: before record/render, HEAD-probe team assets (`probeAssetUrlChain`), confirm background, voices. **Logo hard-gate** blocks if a crest is missing (team-answer runners 1/2/7). Parallelized to stay fast as level count grows.

## BGM
`audio.js`: each save freezes **5 songs** (`script.bgmSongs`, basenames; tracks in `.Storage/Voices/Ringhton/`). `buildBgmSession()` resolves+shuffles them once and loops; `prepareAndWarmBgmSession()` pre-decodes all 5 in preflight (kills switch stutter). 1.2s crossfade; BGM ducks −12dB under voices (only `fadeBgm` writes `bgMusic.volume` mid-flow — `setBgMusicForLevel` must not snap it). `BGM_PLAYLIST` (~31 tracks) is exported for the voice-tab crossfade preview.
